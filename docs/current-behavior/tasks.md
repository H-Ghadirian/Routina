## Current Contract

- Todos and routines share the task model while keeping their distinct timing semantics. If an internal `record`-shaped development row is encountered, every product surface treats it as a routine.
- Free Routina allows up to 10 active tasks. Creating another active task requires an unlimited-task entitlement from a subscription or lifetime purchase; existing tasks are preserved even if the account already has more than 10 active tasks. Development apps can temporarily unlock unlimited task creation from Settings while StoreKit products are unavailable. Production apps ignore this testing override and require a StoreKit entitlement.
- Active-task counting includes todos and routines that are not paused, snoozed, archived, done, or canceled; internal record-shaped rows count as routines.
- One-off tasks and repeating routines can be archived without changing their completion history or other task data. On Mac, one-off tasks use `Archive` / `Restore` in Task Detail, Edit Task, and Home row context menus, while routines retain `Pause` / `Resume`; archived tasks leave active Home placement, notifications, guided `Add missing…` reviews, Help me choose, and task-relationship review until restored. Restoring a one-off task does not create or shift recurrence data.
- Full task create and edit forms offer `One-time` / `Repeating` without a separate third task type. New repeating tasks are routines. Repeating routines can use `Repeat type: None` when they are reusable but have no known cadence; they remain immediately available after completion and preserve every completion in history without cadence-derived occurrences, overdue pressure, nudges, or daily classification.
- On Mac, a successful full Add Task save closes the form, returns to the task list, selects and opens the new task's details, and shows a transient confirmation containing the task name. Canceling, a failed save, or a subscription-gated save does not show that success confirmation.
- Gentle repeating routines expose an independent `Nudges` preference. Turning it off preserves cadence and history while suppressing Ready and Gentle-nudge threshold badges. Due routines do not expose the preference, and cadence-free routines cannot nudge.
- Home, Timeline, Stats, Settings, badges, search vocabulary, and sidebar sections do not expose a separate Tracking category. Transitional tracking-named storage fields remain internal implementation details only.
- Mac Add Task and Edit Task tag sections always show the draft's selected tags and related suggestions. The remaining saved-tag chips default to the six most-used tags and expose `Show all` / `Show less`; autocomplete continues to search the full saved-tag catalog.
- Mac Settings -> Tags separately lists possible duplicate names for conservative word-form variants such as `clean` and `Cleaning`. Each row states the source and replacement tag and opens a confirmation before the global merge updates any data. Confirming uses the existing rename path across tasks, goals, enabled notes, and events, and deduplicates the replacement tag when both occur on the same item; unrelated or semantically ambiguous tags are never merged automatically.
- Todo availability has independent date and time axes. Date bounds, time windows, deadlines, reminders, and planned dates are separate concepts except that one-off todos with exact `At date` availability automatically use that same normalized day as their planned date.
- Planned dates are date-only Home-list planning hints for todos and eligible non-daily routines. They are not availability, deadline, reminder, completion history, or stored Planner blocks. Planner day agendas surface active date-only planned tasks for the selected day.
- Deleting a task also removes persisted task-backed Planner blocks for that task so deleted work does not remain on the calendar.
- Task Detail calendar overdue markers run only while an overdue task is unresolved. If a completion, cancellation, or missed log resolves the task, later days stop showing as overdue.
- Task Details can resolve a selected past exact-time routine occurrence, or today's occurrence after its scheduled time window has ended, even when older missed exact-time occurrences remain unresolved. The top primary action stays Done or Undo for the selected occurrence. On Mac, selecting a single-occurrence day also shows eligible Missed and Canceled actions inside the calendar card. Resolving that selected occurrence does not hide older unresolved missed dates; future dates and non-occurrence days remain unavailable.
- Task Detail shows an occurrence selector on iOS and macOS when a selected day has several atomic routine occurrences. Each scheduled time has its own Done, Missed, Canceled, Ready, or Upcoming indicator; selecting one targets completion and undo at that exact timestamp, and supported exact-time occurrences can be confirmed missed or canceled independently. Changing calendar day clears the transient occurrence selection.
- Task Details hides neutral Priority metadata and History by default. Full details offers both through Add More Details. Legacy Medium/Medium priority defaults stay hidden to match Edit Task; non-neutral priority metadata and explicitly revealed Priority remain visible. Priority and History disclosure choices persist per task through copying and backup/restore.
- Home row actions that resolve missed exact-time or time-window occurrences prefer an unresolved occurrence on the current reference day. Choosing `I did it` after today's time window has ended records the just-finished occurrence before older unresolved missed history.
- Daily routines already belong to the daily routine area and do not expose stored planned-date controls.
- Home `Today` is an additive planning section. It includes active tasks planned for the current day, including pinned and custom-section tasks, plus weekly/month-day calendar routines whose configured occurrence is today. Those tasks also remain visible in their ordinary Pinned, custom, tag, deadline, or regular placement. A calendar routine with a canceled occurrence for today is not shown in the today plan. Rolling interval routines such as `Every 7 days` appear in Today only when explicitly planned.
- On Mac, a task with an effective date-only plan for the current day shows a compact `Planned today` label on its ordinary Pinned, custom, or Future row. Its copy inside Today does not repeat the label because the section already communicates that context. Daily and calendar routines that enter Today only through cadence do not receive the planning label, and the task's normal lifecycle status badge remains visible independently.
- On Mac, daily routines are shown inside `Today`. By default they visually merge into the today list; Settings can restore a nested `Daily Routines` group.
- On Mac, Settings -> General -> Task List can enable the additive `Tomorrow` planning section. It defaults between `Today` and `Future` until the user customizes top-level section order. When enabled, `Tomorrow` contains active tasks explicitly planned for tomorrow, exact-date one-off todos available tomorrow, plus weekly/month-day calendar routines scheduled tomorrow. Those rows also remain in their ordinary Pinned, custom, tag, deadline, or Future placement. The row context menu exposes `Plan to do -> Tomorrow` only while this setting is enabled; choosing it stores tomorrow as a date-only planned date.
- On Mac, a non-empty toolbar search that leaves the normal sidebar sections empty can show a search-only `Search Results` section for matching known task rows that are hidden from normal active placement, such as already-done scheduled tasks, without changing normal section membership after search clears.
- On Mac, user-created top-level custom sections are super sections and each can contain one level of user-created subsections. Row context menus can create super sections, super-section headers can create subsections, and Settings -> Sections uses compact summary cards with one expanded editor to create, rename, reorder, delete, color, and configure super sections plus create, rename, reorder, and delete their subsections. Card headers show color, automatic tags, and subsection count; save/revert controls appear only for unfinished changes, destructive actions live in More menus, and unrelated catalog writes preserve local name/tag drafts. Automatic tag rules use `Any` matching by default or optional `All` matching; configured draft tags render as removable chips, and the tag composer suggests saved tags with Tab completion while still accepting new names. Super-section and subsection headers expose `New Task`, which opens Add Task with that path selected. Mac Add Task and Edit Task always show a `Path` control inside Identity and can assign the task directly to a super section, subsection, or `Automatic`. An explicit assignment shows its custom-section breadcrumb; an unassigned task opened from Task Details shows the same live resolved sidebar breadcrumb with `(Automatic)` instead of a context-free default label. A sidebar-seeded path overrides any restored draft path, and deleted path entries are cleared from an open form. Task-row `Move to` menus let active unpinned tasks move directly into a super section or one of its subsections: leaf super sections are direct commands, while only super sections with subsections open nested menus. Both levels use durable section IDs and their own manual-order keys; subsection rows render as collapsible nested groups inside the super section's full-bleed top-level sidebar surface. Assigned rows are claimed before other ordinary placement, while pinned and archived rows keep their existing ordinary-placement priority. Settings-managed tag rules can claim unassigned rows into super sections; manual assignments remain stronger. Planned-today and planned-tomorrow custom-section rules are unavailable, and legacy saved values are inert. Planning and custom assignment coexist, so a planned custom task appears in both sections only when it has an independent manual assignment or matching tag rule, and neither action clears the other. Deleting a subsection clears only that bucket's assignments, while deleting a super section also deletes its subsections and clears all affected assignments/manual ordering without deleting tasks. Existing flat custom sections decode as super sections.
- On Mac, `Today`, `Tomorrow`, `Future`, and `Archived` use full-bleed section surfaces for their headers and expanded content so their rows visibly belong to those sections. These top-level surfaces use square horizontal edges without colored left or right borders. Mac sidebar task cards keep a small gap between rows.
- On Mac, right-clicking an eligible durable top-level task-list section exposes `Move Up` and `Move Down`; unavailable boundary directions are disabled. Pinned, custom super sections, Future, and Archived can move one visible section position at a time into a persistent display order, while Today and Tomorrow never expose either command. The task list has no section drag handles or section drop targets. This display order is backed up and restored, survives a section becoming temporarily empty or filtered out, and does not change task routing, planning projection, Settings custom-catalog order, or row order inside a section. Newly available sections enter beside their canonical default neighbors; temporary search-only results are not reorderable.
- Home task-list grouping offers `None`, `Deadline Date`, and `Tags`; legacy saved `Status` grouping preferences normalize to `Deadline Date`.
- On Mac, normal active tasks without stronger ordinary placement are grouped under a collapsed-by-default `Future` section, including tasks also projected into `Today` or `Tomorrow`. Existing deadline, tag, and ungrouped inner organization and manual ordering are preserved inside `Future`; when Deadline Date is active, all titled `Future` buckets use the same collapsible inner-section surface, while tag groups keep their color treatment. When grouping by Tags, the Task List Sort panel can optionally show `Missed`, `Overdue`, and `Due Soon` as separate collapsible `Future` groups before the remaining tag groups, and can also split mixed `Future` tag and untagged groups into independently collapsible `Todos` and `Routines` child subsections without changing the parent tag collapse or manual-order identity. Right-clicking the `Future` header exposes `Expand All` and `Collapse All Subsections` when collapsible inner groups exist; these actions open `Future` and batch-expand or batch-collapse its collapsible inner groups, including nested task-kind child subsections.
- Routines separate schedule behavior from format. Due/Gentle controls pressure and status; Interval/Calendar controls cadence; Standard/Checklist controls finish behavior.
- Adding checklist items to a routine that previously had none promotes Standard completion to Checklist completion when no sequential steps would be discarded. Existing Standard routines that already carry checklist items remain editable as legacy optional checklist data.
- Auto-assume done is opt-in for eligible repeating tasks: daily repeats and scheduled patterns with at most one occurrence per day, including weekly, monthly, and yearly schedules. An assumption is derived only on a day with a scheduled occurrence. Eligible Standard multi-day `After done` routines can also opt in: after the interval from the latest real completion elapses, every overdue day remains assumed done until the person confirms one day individually; that confirmation resets the rolling anchor, and these suggestions cannot be bulk-confirmed. A Standard one-off task can also opt in when it has exactly one availability date and a scheduled `Time block`; its one assumption begins at that block's start and applies only to that date. Date windows, all-day tasks, exact times, and Available windows do not qualify, nor do one-off tasks with steps or checklist items. Standard routines must not have steps or optional checklist items; Checklist-completion routines must have checklist items and no steps. Other todos, cadence-free entries, item-runout routines, Standard routines with optional checklist items, step routines, and multi-occurrence-per-day schedules do not qualify. Assumed occurrences are synthetic until confirmed; they do not create completion history. Scheduled Calendar time and all-day blocks remain visible by default while assumed done; enabling `Hide assumed-done blocks from Calendar` for that task restores the hidden-block behavior.
- iOS and macOS Add Task and Edit Task use one recurrence composer instead of exposing Simple and Advanced models. Users choose `No schedule`, `After done`, `On schedule`, or eligible `Item runout`, then see only the frequency and calendar selectors that behavior needs. `After done` presents its interval once in the editable stepper row instead of repeating the same sentence as a summary. On Mac, Completion and Repeat remain stationary; enabling cadence adds one collapsed `Schedule details` row afterward summarizing duration, timing, and Due/Gentle behavior. Item-runout checklist composers keep the item title, `Every N days` interval, and Add action together. Shared multi-select controls preserve every weekday, monthly date, yearly month, and yearly date selection. Dates 29–31 have an adaptive-date indicator and explain that shorter months use their last valid day. iOS keeps compact fill-width cadence/frequency controls; macOS sizes those segments to their labels inside the bounded form measure so partial rows do not stretch across the editor.
- iOS Add Task and Edit Task use a compact grouped hierarchy: Task Type, Duration, and Availability are separate sections; multi-option date and time availability use readable native navigation pickers; and the emphasized task-name field anchors the form. Empty optional fields stay behind a full-row `Add details` menu that reveals and scrolls to one chosen section instead of expanding the complete advanced form. Populated optional sections remain visible, and Edit Task keeps deletion last. Segmented controls and schedule-preview badges inside this scrolling form use lightweight tinted fills instead of independent Liquid Glass backdrops, including when Repeating reveals several controls together.
- Tasks store an optional Description independently from experimental Notes. Add Task and Edit Task expose it as a progressive section on both platforms; Task Details displays it with its own label and offers a field-specific add action when it is missing. Description remains available when the Notes beta is off, while existing task notes and voice notes keep their feature gate. Draft restoration, copying, Home and AI search, sharing, sync repair, and backup/import preserve Description.
- `More schedule options` progressively reveals fixed start, time zone, occurrence times, hourly daily windows, and end date/count. Optional fixed scheduling uses a grouped switch; mandatory fixed details show `Required` instead of a disabled control. Mac forms keep the inset controls leading-aligned, summarize active fixed details in the collapsed row, and present single-time weekly/monthly/yearly Start date plus At time once while keeping the underlying threshold aligned. The disclosure opens automatically for every-N fixed schedules, hourly/yearly schedules, ordinal weekdays, multiple daily times, or ending conditions. If several adaptive monthly dates resolve to the same shorter-month date, Routina produces one occurrence for that timestamp.
- Add Task, Edit Task, and the shared form model edit one lossless draft spanning cadence-free, item-runout, after-completion, compact calendar, and fixed-anchor structured schedules. Compact and Advanced persistence remain internal compatibility strategies. Draft transitions preserve exact-time intent and date/time availability remains a separate module.
- Fixed date-based structured schedules can compose with an Available window or Time block. For at most one occurrence per day, the range start is the effective occurrence timestamp and the range end closes it. With several explicit daily occurrence times, each scheduled time remains a separate history identity while the range is their shared daily actionability boundary. Home, Task Detail, notifications, missed resolution, and Planner use the same contract. Hourly schedules still reject a separate outer range because hourly generation already owns its continuous-or-daily-window boundary.
- Fixed-anchor calendar occurrences stay anchored to the configured start rule rather than shifting when completed. Subdaily and multi-time daily routines keep separate scheduled completion timestamps on the same day and become actionable again when the next occurrence is due; compact completion remains day-based.
- Task Detail can mark an active, one-day, untimed, single-occurrence `On schedule` routine done before its due date. History records the actual completion time, a separate occurrence identity records which scheduled occurrence was satisfied, and the next due date stays anchored to the configured calendar rule. A satisfied occurrence does not reappear in its Home `Today` or enabled `Tomorrow` planning projection when that calendar day arrives; the active recurring task retains its additive ordinary placement with the next due status. Home actions, timed/windowed or subdaily schedules, checklist completion/runout, and multi-day routines retain their normal due or lifecycle boundaries.
- Advanced reminders schedule a bounded rolling set of upcoming occurrences and rebuild that set after completion or edits. Simple reminders retain their existing single pending request.
- CloudKit direct pull preserves structured Advanced and multi-selection recurrence even when the same record also contains simplified compatibility columns. Ordinary single-value Simple recurrence continues to use the typed columns.
- Editing an existing interval routine from one interval frequency to another preserves its current rolling schedule anchor, so the new cadence recalculates from the existing completion/history anchor rather than from the edit timestamp.
- Multi-day routines use a `Start` -> in-progress -> `Stop` lifecycle. Their detail calendar shows an ongoing range while active and a completed span after stopping. One-day routines, including Gentle and checklist-driven routines, do not expose a separate `Start ongoing` action on either iOS or macOS; legacy one-day ongoing state remains finishable for compatibility.
- Checklist runout item actions are item-scoped. Task Details can update today or a selected past day, using the selected day as the runout reset date; future dates remain read-only. Completing all currently due items for that selected day records routine completion.
- Checklist item intervals are stored as meaningful cadence only for checklist runout routines. Checklist-completion routines and optional checklist data normalize item intervals to a neutral one-day value.
- Daily checklist-completion progress lasts for the current day only. Tomorrow starts unchecked unless the routine was completed and recorded in history.
- Daily Checklist-completion routines with auto-assume done use day-level assumption only; assumed completion does not fake completed checklist item IDs, and current-day partial checklist progress suppresses assumed presentation until the routine is fully completed or progress is cleared.
- Home shows assumed-done rows by default and no longer has a `Show assumed done` task filter. On Mac, hovering an assumed-done Home row shows green check and red x actions for confirming the current assumed occurrence or recording it as missed.
- Home task filters include an Estimation filter with `All`, `Has Estimate`, and `No Estimate`; it applies to visible and archived task rows on iOS and macOS and persists with each task-list mode's filter snapshot.
- Tasks store an independent `Thinking needed` complexity level (`None`, `Low`, `Medium`, or `High`) for the understanding, concentration, and decision-making they require. It is available in Add Task, Edit Task, and Task Details on iOS and macOS; exact Home filters include `All` plus every level and persist with each task-list mode. Thinking needed is preserved through copying, sharing, sync repair, and backup/import, and does not change task duration, pressure, priority, scheduling, or ordering.
- On Mac, the Planner header filter button opens `All`, `Task List`, `Timeline`, and `Calendar` filters in one right-side companion pane. Tags and importance/urgency live under `All` and apply to task-list, Timeline, and task-backed Planner Calendar filtering. The pane can expand fullscreen and minimize back, while preserving the active workspace underneath. Task and Timeline sidebars no longer render their own filter icon buttons, but active task filters can still show summaries and clear actions in the sidebar.
- Home task filter Query sections are unavailable in production. Development builds can enable them through Support & About -> Beta Experiments -> `Show filter query sections`; existing advanced query state remains compatible.
- Home status filters offer `Done Today` only for `All` and `Routines`; Todos use Timeline for completed work instead of keeping completed rows in the active task list.
- Once a checklist-completion routine is completed for a selected day, its checklist rows present as checked and read-only from selected-day completion evidence, even though in-progress checklist IDs are cleared after the final item. The toolbar Undo action reopens/removes the completed day without flashing stale completed checklist state back into the rows.
- Selected checklist item mutations keep their post-action detail state through stale Home reloads, including final completion after item-progress IDs reset.
- Optional checklists attached to ordinary tasks can block manual completion until all required items are checked.
- Task links can fulfill routines. `Done when` / `Completes` links are automatic when the source task is completed. `Can complete` / `Can be completed by` links are manual: Task Detail asks whether the source completion should also fulfill eligible linked target routines, and selected targets record source-attributed fulfilled logs without increasing aggregate completed-activity stats.
- Task Details on iOS and macOS exposes linked-task controls for every task and can request bounded Apple Intelligence suggestions on demand. Candidate discovery considers shared tags, task-path components, and concrete work words; the on-device request includes bounded descriptions, custom-section paths, deadlines, planned/availability dates, scheduling context, steps, and checklist items, but excludes ranking and personal-preference fields. A request uses at most eight candidates. When a catalog is larger than that, only candidates with specific discovery evidence enter it: generic action words and work words common across the catalog do not qualify, and zero-signal tasks never fill spare slots. A shared path is evidence for finding candidates, not proof of a relationship. Routina proposes at most three validated `Blocked by`, `Blocks`, or `Related` candidates with reasons grounded in concrete task details; the person can change the type, dismiss the proposal, or confirm it. No relationship is created before confirmation. A dismissal stores only a device-local, fingerprint-scoped task-pair record; unchanged pairs are excluded before later model requests and an edit to either task expires that record. The existing manual create/link actions remain available when suggestions are unavailable or incomplete. On Mac, the Routinam application menu also opens a dedicated `Review Task Relationships` window: a lazy task catalog shows task paths, existing-link counts, `New`/`Changed` state, pending-proposal badges, durable unchanged checks, and per-task analysis failures. The primary action analyzes only tasks whose device-local bounded-summary fingerprint is missing or changed; priority/ranking-only changes do not invalidate it. A task is marked current only after no proposal is found or all proposals are resolved. `More` retains selected-task analysis and explicit `Reanalyze all tasks`. Batch runs reuse one immutable summary catalog, make bounded model requests sequentially, show live progress, support cancellation, deduplicate task pairs, and collect proposals into the same editable confirmation queue. A content-specific model failure marks only that task for retry and the batch continues; unavailable Apple Intelligence still stops the run. Analysis never starts when the window opens or writes a relationship automatically.
- Mac Task Details and Edit Task use the same compact linked-task action row: a relationship picker followed by `Create New Task` and `Link a Task`. The chosen relationship seeds new-task creation and initializes the existing-task picker. In Task Details, the first `Link a Task` click opens that picker directly without revealing a second Linked Tasks editor; choosing a task saves the new relationship immediately. Edit Task keeps relationship changes in its normal draft until Save.
- Task place sections, linked-place badges, place-based task filters, and task-row Places appearance controls are hidden while the Places beta setting is off.
- Home task lists derive visible sections from one stable presentation model. Each task ID is claimed once within ordinary classification and deduplicated within each section. A task may intentionally have one additional row in Today or Tomorrow because planning is an additive projection. Section and group identity is based on durable keys rather than visible titles.
