## Current Contract

- On Mac, Planner, Backlog, and Task Ladder keep the persistent top `Search or create a task` control while owning independent queries and presentations. Planner continues to filter its task sidebar and Calendar together. Task Ladder search matches task metadata and ancestor group names across root and nested scopes; eligible results report their Ladder path and current metric value, and `Locate` enters the owning scope, reveals and highlights the row, and preserves rank order. Matching tasks excluded from the Ladder remain separately identified with their lifecycle, Blocked, Flag, or prerequisite reason. Any existing task result in the global catalog suppresses creation, regardless of the active workspace.
- Flags are fixed built-in behavior markers rather than user-created rule containers. The four available behaviors are Hide from Task Lists, Hide from Timeline, Hide from Task Ladder, and Auto Assume Done; a task may carry several at once. Ordinary personal labels are Tags. Launch maintains the canonical built-in catalog without scanning or rewriting task assignments.
- iOS Add Task, Edit Task, and Task Details let every Flag chip use its full intrinsic label width and wrap to a later row before truncating.
- Todos and routines are the only task kinds in the model and persistence schema, and they keep distinct timing semantics.
- Task creation is unlimited on iOS and macOS. Full Add Task, Smart Add, toolbar creation, and Quick Add never count existing tasks or require a purchase entitlement before saving another task.
- The shared Smart Add and Quick Add parser recognizes English day-month dates such as `25 August` and an optional matching weekday such as `Tuesday, 25 August`. Without a year it chooses the nearest occurrence on or after the reference day that satisfies the supplied weekday; an explicit year is used as written. A 24-hour time can follow with or without `at`, so `Physiotherapist Tuesday, 25 August 15:00` becomes a one-off todo named `Physiotherapist` with `At date` availability on 25 August and `At time` availability at 15:00. It does not infer a deadline or reminder. Explicit `due` or `by` wording creates a deadline instead, still without silently adding a separate reminder. iOS Smart Add shows one-off date/time availability as an `Available` row in its Detected section before saving. On the Mac toolbar Quick Add preview, pressing Enter snapshots the displayed editable title and selected reminder together with the active parsed draft before asynchronous creation starts. Continuing the same composition by appending or deleting text, making a one-character edit, or adding or changing metadata such as a tag preserves the selected reminder; replacing or clearing the task starts fresh. The selected reminder is calculated from the submitted draft's exact availability and persists on the task; reopening Edit Task loads it. These parser rules are shared by iOS Smart Add, Mac Add Task title parsing, and the Mac toolbar search-or-create path.
- When a one-off task has an exact availability time and the person changes Time availability to `Time block` or `Available window` in Add Task or Edit Task, the first range inherits that exact time as its start and uses the standard three-hour range duration. A reminder that was relative to the exact time remains relative to the inherited range start, so its saved date and time do not jump during the mode change.
- The shared parser extracts pasted HTTP/HTTPS URLs before interpreting other syntax and saves them as task links. URL-only input immediately gets an editable deterministic title such as `Watch YouTube video`, `Review GitHub link`, or `Open example.com`; text beside the URL remains authoritative. Mac toolbar Quick Add can asynchronously replace an untouched fallback with a page-specific title and preserve the resolved page title on the link. While the same URL remains in a continuously edited query, the URL alone identifies the metadata request, so typing another character or adding a tag neither refetches it nor clears an edited preview title. Changing or removing the link starts fresh. Metadata failure never blocks creation, user edits stop automatic title replacement, and saved tasks are never renamed afterward. Local, private-network, credential-bearing, and non-HTTP destinations do not trigger metadata requests.
- After Mac toolbar Quick Add first confirms recognized metadata for a no-result create candidate, the Detected details rectangle remains mounted while that expanded composition continues. New parser drafts update its title and rows in place; a non-empty value that is temporarily unparsable shows `Updating details…` without stale controls. Live search refreshes do not remove the rectangle. It leaves the visible presentation after creation, Clear, Escape or outside collapse, or when the current search is confirmed to match an existing task or Timeline-style result.
- Active-task counting includes todos and routines that are not paused, snoozed, archived, done, or canceled.
- One-off tasks and repeating routines can be archived without changing their completion history or other task data. On Mac, one-off tasks use `Archive` / `Restore` in Task Detail, Edit Task, and Home row context menus, while routines retain `Pause` / `Resume`; archived tasks leave active Home placement, notifications, guided `Add missing…` reviews, Help me choose, and Calendar scheduling until restored. Task Detail also offers `Pause Until…` / `Archive Until…` with a local date and time: the task is hidden from Calendar scheduling until that instant and then becomes active automatically. An indefinite pause remains hidden until manually restored. Restoring a one-off task does not create or shift recurrence data.
- Full task create and edit forms offer `One-time` / `Repeating` without a separate third task type. New repeating tasks are routines. Repeating routines can use `No schedule` when they are reusable but have no known cadence; they remain immediately available after completion and preserve every completion in history without cadence-derived occurrences, overdue pressure, nudges, or daily classification. They can instead use `When needed` when the next use is unknown and the person wants the task to pause automatically after each completed occurrence: completion enters the existing paused/archived lifecycle, the task leaves active projections, and `Resume` makes it available again while retaining the `When needed` setting for the next completion. Undoing the latest completion also removes that automatic pause. After today's first `No schedule` completion, the iOS Task Detail action becomes `Log another completion` so further entries are explicit. `No schedule` and `When needed` share cadence-free storage but have intentionally different post-completion availability.
- On Mac, a successful full Add Task save closes the form, returns to the task list, selects and opens the new task's details, and shows a transient confirmation containing the task name. Canceling or a failed save does not show that success confirmation.
- Gentle repeating routines expose an independent `Nudges` preference. Turning it off preserves cadence and history while suppressing Ready and Gentle-nudge threshold badges. Due routines do not expose the preference, and cadence-free routines cannot nudge.
- Home cards and Task Detail derive elapsed-completion text from the newest recorded completion across history and the task summary. The task summary's `lastDone` remains the recurrence cursor, so a delayed or independently synchronized summary cannot make a Home card report an older elapsed time than Task Detail or Calendar.
- Task-kind storage, forms, filters, search, Home, Timeline, Planner, Stats, Settings, badges, and sidebar sections use only Routine and Todo. The pre-release third-kind compatibility enum, schedule modes, schema fields, aliases, and migration branches have been removed.
- iOS Search keeps keyboard input immediate while task-list results update after a brief idle pause; clearing the query updates results immediately. Selecting the dedicated bottom Search tab activates its native field and opens the keyboard in the same tap, while activating Search preserves the existing tab host instead of rebuilding it. Task display snapshots cache normalized searchable metadata, and non-actionable full-catalog filtering, sorting, section construction, and restored-list row-number lookup run as cancellable value-snapshot work away from the main actor. Search keeps one native list mounted across result and empty states, only the empty-state overlay receives the short opacity transition, and visible row metadata does not reconstruct the full Home filtering configuration.
- Retained iOS Home, Search, and Timeline tabs defer synchronization-driven fetches and presentation rebuilds until their tab is active. Home's full-history repair work runs only while establishing its initial snapshot; ordinary updates use the lightweight load path. While an active Home or Home-backed Search list is scrolling, persistence notifications collapse into one pending refresh, and task plus attachment fetching waits until the list has been quiet for 1.2 seconds. An ordinary Home load does not rewrite unchanged temporary filter state, so it cannot create a preference-sync update that schedules another load. iOS Home pull-to-refresh and the Mac Home sync action show a linear activity banner with the exact received-item count, let an active direct CloudKit transfer continue, stop it after 60 seconds without activity, and retain a three-minute hard limit. Home does not invent a completion percentage because CloudKit does not report the total pending item count. A successfully merged pull saves a per-container change token so later manual refreshes fetch only newer changes. A failure ends progress, reloads unchanged local data, explains that the data is safe, and offers a retry rather than leaving the refresh pending indefinitely.
- iOS foreground Focus reconciliation queries only active CloudKit Focus records and directly refreshes the bounded set of active local timer IDs rather than replaying task and history records. An explicit full sync batches all received deletion IDs and scans related history once per pull.
- Settings -> Flags defines task-only flags and their extensible behavioral rules, independently of tags. Add Task and Edit Task offer every defined Flag as a selectable chip, initially showing six with `Show all` / `Show less` for larger catalogs. Task Details show each assigned Flag. Mac Task Details place assigned Tags and Flags in one neutral metadata card, retaining separate headings and chip treatments. When the full unwrapped content fits, both groups share one horizontal row with a vertical divider; otherwise they use two labeled rows with a horizontal divider and wrapping chip collections. A lone Tags or Flags group uses the same adaptive fit without an empty group or divider. On iOS, these variable-width Flag chips wrap before truncating so available space is not left unused. `Hide tasks from normal task lists` removes tasks carrying that Flag from ordinary Home task-list placement, including Pinned, Today/Tomorrow, custom sections, Future, tag groups, and Archived. It does not archive or pause the task, affect notifications, Planner, or active-task counting. `Hide tasks from Task Ladder` independently removes matching tasks from every Mac Task Ladder metric without changing their placement or behavior anywhere else. `Hide task activity from Timeline` omits matching task logs and task-linked Focus sessions from the default iOS Timeline and Mac Planner Timeline; the activity remains intact and selecting its Flag in Timeline Filters deliberately reveals matching activity with `All` / `Any` matching. Home task-list Filters can select assigned Flags with `All` / `Any` matching; a matching task otherwise hidden by the normal-task-list rule appears only in the presentation-only `Hidden by flag` section without normal inline completion actions. Text search matching the task, its text, or its Flags can produce that same section. On Mac, a Task Detail breadcrumb from that result names the selected task's hiding Flag or Flags. Board and Planner Calendar remain unaffected; Stats has its own independently selected `All` / `Any` Flag include/exclude filters.
- iOS and macOS Task Details place populated Description, Links, Image, File or Files, Voice Note, and Notes content in one shared scrolling card. The card omits a generic `Details` title and labels only the content types that are present, in that order. Notes and Voice Note still follow the Notes feature gate. Links remain openable and copyable; the Mac image keeps its full-surface open action and 320-point maximum display height. On Mac, these links no longer occupy a separate link-only `DETAILS` box in the compact header overview; the content card appears for a link-only task and stays absent when every supported content type is empty.
- On Mac, choosing Backlog from the main window's workspace menu or pressing Shift-Command-B opens a full-size workspace in that window for work intentionally kept off the Home sidebar radar. The Backlog workspace has no generic, unsectioned destination and no persistent section composer. A Home task row's `Move to > Backlog` menu, or a Backlog task's equivalent menu, can create `New Backlog Super Section…` and immediately assign the selected task; Settings remains the path for preparing an empty Backlog catalog. Backlog destinations are nested beneath one `Backlog` menu in the Main task list, with one additional level for subsections. Add/Edit Task's `Path` menu continues to offer destinations labelled `Backlog › <section>` when sections exist. Backlog super sections and one nested subsection level are durable custom paths. Empty catalog sections remain visible, both hierarchy levels have full-width collapsible headers and task counts, and each expanded super section can create a subsection immediately; search temporarily treats matching hierarchy as expanded without overwriting the person's disclosure choices. Moving a task into a Backlog path removes it from the normal sidebar and search fallback, while `Move to Radar` restores normal Home placement. The persistent top `Search or create a task` field owns a Backlog-specific query and replaces the former duplicate sidebar field. It filters the cached Backlog presentation across task title, emoji, description, notes, destination, tags, Flags, and section path; `Hidden by flag` tasks participate. Main task list and Backlog super sections evaluate their automatic tag rules independently. A tagged Backlog super section automatically claims matching active hidden-by-Flag tasks for presentation even when they retain a Main task list assignment, using the first matching Backlog super section; the stored Main task list path is not overwritten and becomes visible again when the hiding Flag is removed. An explicit Backlog assignment remains stronger than Backlog automatic rules, ordinary tasks without the hiding behavior are not pulled into Backlog, and subsections remain manual. Matching tasks outside Backlog remain in a separate `Found outside Backlog` group with their Radar/custom path or lifecycle location. Clicking a result summary opens its standard Task Details; active, canceled, and archived matches can preserve the query and hand off to Planner, while a completed one-off match hands off to the filtered Timeline and its recorded activity. Any match can move to an explicit Backlog destination. These results never count as Backlog matches, and their existence suppresses task creation. Backlog and Task Ladder embed full Task Details without contributing a second native principal title above the shared toolbar. Leaving Backlog while a detail is open clears the embedded detail before replacing the workspace split hierarchy. When an unmatched Backlog query starts task creation, the chooser labels each destination explicitly as `Backlog › <section>` and names the non-Backlog option `Main task list`; choosing that option opens the regular task form without a Backlog path. The beta Board's default and named backlogs are a separate one-off/sprint organization system and do not create destinations in the Backlog workspace. The workspace also automatically lists active tasks hidden by a `Hide tasks from normal task lists` Flag until they receive an explicit Backlog path. Backlog task rows open the standard Task Detail and Edit flow. Older custom sections remain normal sidebar paths unless explicitly created as Backlog sections. Backlog refreshes through Routina's coalesced semantic update path rather than every raw persistence save. Automatic refreshes replace the snapshot silently; only initial loading and an explicit manual refresh use the visible loading state, so background sync cannot flash its controls or empty-state surface. Hierarchy and search filtering are rebuilt only at task, section, Flag-rule, or search-input invalidation boundaries; scrolling rows consume the stable snapshot.
- On Mac, Task Ladder is a full-size workspace available from the main-window workspace menu or Shift-Command-R. Its cached ranking snapshot excludes paused, snoozed, blocked, completed, canceled, archived, and Hide-from-Task-Ladder tasks without mutating their Home or Backlog placement. Pressure, Urgency, Importance, Thinking, and Estimated time render as independent sortable views with `No value` or `No estimate` sections. Categorical rows can be reordered within a value or moved across values to update only that metric; each metric remembers independent tie-break ranks and direction. Estimated time stays factual and read-only.
- Task Ladder supports container-only groups and repeating tasks explicitly enabled as task groups. `Use as Task Ladder group` belongs to Add/Edit Task's Organization section and stays out of Task Details. Empty enabled task groups remain reachable; groups with children cannot be disabled until the children move. Nested placement is independent from completion relationships, rejects cycles, and keeps manual, automatic, or no-completion behavior explicit. Container values may be explicit, `No value`, or inherited from the highest actionable direct child without mutating stored group or task data. Deleting a container returns children to the root. Task-backed groups use normal Task Details; container groups use a group summary. Task rows, group rows, suggestions, inherited state, child counts, and relationship blocking are all derived at snapshot invalidation boundaries rather than during scrolling.
- A repeating Due routine with active interval or calendar cadence can use `Changes over time` inside its Task Ladder values. One-time Add and Edit forms omit temporal choices; repeating forms either show them or name the exact Behavior & Schedule choice required to enable them. iOS and macOS use the same picker-only sentence editor. Each Importance, Urgency, and Pressure sentence directly chooses the stored `After done` value, whether that metric changes, its own higher target, its own timing mode, and its own day count when applicable; Thinking has its own After done picker and does not change over time. `Only on due date` applies the target on the due date and while overdue. `Gradually before due` advances categorically over that metric's lead window and reaches its target on due. `Gradually while overdue` stays at After done through the due date, then advances one categorical level after each configured number of full overdue days until its target. For an After done cadence, every before-due window is capped to the repeat interval, so a two-day recurrence cannot start inside a nominal seven-day window. Turning every metric to `does not change` removes the rule. Existing shared-curve storage decodes by assigning its old timing to each old target and is rewritten in the independent format on a later save. Task Details shows the configured After done/Now/per-metric-policy summary as read-only and directs changes through full Edit Task. Mac Task Ladder offers the same sentence editor from the row context menu and can save the After done values and policies together. Task Ladder's Base view remains editable, while Now derives effective values without mutating Base and is read-only. Completing an occurrence advances its due date and resets the new occurrence to the After done values. Unsupported rules are removed when an edit is saved. Inherited groups use child Base values in Base and child effective values in Now. The cached snapshot refreshes after task changes and at the next calendar-day boundary while Now is active; the rule remains included in task sync, sharing, backup, and import.
- Mac Add Task and Edit Task tag sections always show the draft's selected tags and related suggestions. The remaining saved-tag chips default to the six most-used tags and expose `Show all` / `Show less`; autocomplete continues to search the full saved-tag catalog.
- iOS Add Task and Edit Task keep selected and contextually related tags visible, with the six most-used remaining saved tags as compact suggestions. Each inline tag chip uses its full intrinsic label width and wraps to a later row only when necessary. `Browse all tags` opens a multi-select searchable list for the full catalog; inline tag entry and autocomplete remain available for creating or finding a tag without opening it.
- iOS Settings -> Tags keeps each saved tag to its name and usage summary until the person selects it. The selected row alone reveals its fast-filter, rename/delete, color, and optional related-tag controls; selecting another tag moves those controls, and selecting the open tag again collapses them. This temporary selection is never persisted.
- iOS Add Task and Edit Task present Importance and Urgency as separate controls. Home, Stats, and Timeline Filters group separate compact Importance and Urgency threshold rows under Priority; Home groups its existing Pressure and Thinking needed rows there too. Each row opens a persistent dedicated sheet, `All` includes every level on that axis, and changing one threshold preserves the other. The stored combined threshold, matching, clearing, and persistence behavior remain unchanged.
