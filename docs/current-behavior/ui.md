## Current Contract

- The macOS main window uses a labeled workspace menu for Planner, Backlog, Task Ladder, Stats, and enabled Goals or Adventure surfaces. Backlog and Task Ladder replace the main content as full-size peer workspaces instead of opening separate windows. Settings is visible in the menu but opens the standard macOS Settings window, and New remains a separate action.
- iOS uses Home, Search, New, Stats, and Settings as its standard primary tabs, in that order. Regular-width layouts can additionally show Goals when that feature is enabled. Timeline and More are not tab-bar items; restored More state resolves to Settings.
- The iOS Home task list ends with native Backlog, Timeline, and Task Ladder rows in that order. They open inside Home's existing navigation hierarchy and do not change the bottom tab bar. Compact iPhone and iPad layouts use one native navigation stack from Home through these workspaces and their descendants; regular-width iPad layouts retain a sidebar/detail split. In Task Ladder, activating a group row pushes Group Details above the current Ladder, while the explicit inner-ladder control pushes that group's ranked list. The native Back button or interactive back gesture therefore reveals and returns to the preceding Task Ladder list before it can return to Home. The dedicated Search tab omits these workspace rows. A genuinely new installation with a loaded empty task snapshot instead shows one `Create Your First Task` Home state without task-type actions, Filters, or workspace rows. Once that installation observes any task, the first-task state is permanently complete; a later empty Home keeps `Add New Task` and shows all three workspace rows below it.
- Timeline can render inside an existing iOS navigation hierarchy without creating a second compact navigation stack or iPad split hierarchy. Its ordinary route is the native Timeline row at the end of Home; legacy deep links and restored Timeline state use a non-tab fallback sheet. Both routes reuse the same Timeline feature state while loading only when their visible route is active. Each task-backed Timeline row owns its Task Details destination directly instead of registering a value type on the surrounding shared stack, so activating it pushes one details screen above Timeline and Back returns to the Timeline list before a later Back can return to Home.
- Mac Add Task is a transient workspace. Cancel returns to the workspace that launched it, including Backlog, while a successful full-form save keeps the existing behavior of selecting the new task in Planner. If the app relaunches while Add Task was open, the launching workspace—not Add Task—is the restored destination.
- The native left task sidebar and its titlebar toggle belong to Planner-style task navigation; Backlog and Task Ladder hide that toggle while their full workspace is active. Right-side panes remain contextual companions for filters, Go to date, and task details, with one companion role active at a time. Routina does not place global navigation in a second right drawer or a modal overlay drawer.
- The Mac Planner Focus picker shows the locally remembered duration as Last choice and selects it by default. It uses the latest attributed Focus session only when no picker duration has been saved, while task selection remains explicit.

- Visible button targets are interactive across their full visual surface, not only across their text, emoji, or icon.
- Native SwiftUI button styles may own their native hit areas.
- Custom or plain buttons must make the intended button surface fill the target and define a matching `contentShape`.
- Routina glass-backed cards, pills, and panels provide rounded hit shapes through their shared visual modifiers so new glass-backed buttons inherit the rule by default.
- Shared glass segmented controls keep selected labels dark against their bright selected glass surface in both light and dark appearance.
- Mac Stats keeps Scope, Show, Time Range, Importance, and Urgency as native menu-style pickers inline with their titles in passive colored cards. The controls do not expand or move later filters; only selecting Custom Range reveals its two date fields. Stats Flags and Tags keep Stats-owned state but reuse Planner Shared's always-expanded orange and teal panels, visible rule summaries, and one combined Include/Exclude searchable popover per panel. Query retains its separate complex interaction.
- Task-backed Mac Stats rectangles are full-surface, keyboard-focusable controls. Clicking one, or pressing Return or Space while it is focused, opens an anchored evidence popover at that rectangle; the popover scrolls lazily when its grouped task or focus-source rows exceed the bounded height.
- User-facing task-type choices use `All`, `Repeating`, and `One-time` across Add/Edit, Home, Timeline, Stats, Goals, and Settings. Internal `Routine` / `Todo` raw values remain persistence and import compatibility details and are not rendered as task-type labels. The iOS Home Filters Task Type detail presents those choices as full-width native grouped rows with symbols and a selection checkmark.
- iOS Home, Stats, and Timeline Filters show their available choices together as compact current-value rows without a separate heading repeating a row's name. A Priority heading groups the independently named Importance and Urgency rows on all three surfaces plus Pressure and Thinking needed on Home. Each row opens a persistent detail sheet whose navigation title names the choice once; inline pickers suppress the same visible label while retaining their accessibility label. Home's Task Type, One-time State, Importance, Urgency, Pressure, and Thinking needed details use native grouped-row pickers. Importance and Urgency spell out minimum thresholds; Pressure and Thinking needed distinguish the unfiltered `All` choice from the exact `None` value. The four Priority filters remain independent. The Tags entry opens the searchable catalog only when selected, so the primary filter sheet never expands every saved tag. Timeline adds a searchable Flags entry when task-backed activity exposes Flags; selecting one or more deliberately reveals matching activity, including entries hidden from the default Timeline by a Flag rule. Clear Filters remains a separate direct primary-sheet action.
- iOS collapsible Home section headers show their compact task count with secondary contrast so the number remains readable in light and dark appearance.
- iOS Timeline renders from a stable explicit SwiftData snapshot and refetches it on appearance, app activation, and Routina's semantic update notification so newly imported CloudKit activity appears without reopening the app or waiting for a long-lived query to invalidate.
- iOS Timeline's Type sheet and horizontal type controls follow feature availability. Events and Emotions require `Show Event and Emotion features`; Sleep requires both `Show Away` and `Show Sleep tab`; Notes, Places, and Away retain their own gates. Turning a gate off removes its type choice immediately and normalizes a stale selection back to `All`, so unavailable selections do not remain active or keep the filter button highlighted.
- The iOS bottom-bar `New` action always opens a chooser with exactly two full-row actions in stable order: `Create Task`, then `Focus`. Create Task opens the existing Smart Add flow. Focus deliberately loads eligible active tasks and tags only after selection, then offers count-up and fixed-duration choices. If a task, tag, unassigned, or sprint Focus timer is already active, Focus opens that timer's controls instead of allowing a conflicting start. Event, Emotion, Note, Goal, Check In, Away, and Sleep do not appear in New.
- The iOS shake-to-sleep shortcut requires `Show Away`, `Show Sleep tab`, and `Shake to start sleep mode` to all be enabled. Turning any of them off immediately removes the shake listener, dismisses a pending shake confirmation, and prevents a stale shake or confirmation action from starting Sleep mode.
- A truly empty iOS Home list shows `Add New Task`. When a non-empty Home search has no matching known task, its no-results state shows `Create Task`; both actions open the shared Smart Add sheet, and the search action pre-fills it with the trimmed query. If a known task matches but current filters hide it, Home omits the create action to avoid suggesting a duplicate.
- The former development task-review procedures retain their reducer and view implementation for compatibility, but iOS no longer exposes them through primary navigation after the More tab's removal.
- iOS and Mac Add/Edit present Importance and Urgency as separate four-level controls, with the same visual treatment as Pressure and Thinking needed. iOS Task Details can add either field independently with separate picker pills. Mac Task Details keep the four independent Importance, Urgency, Pressure, and Thinking needed controls together inside the expandable Priority card. Saving one field never marks the other explicit. Derived Priority remains internal sorting metadata. iOS Home, Stats, and Timeline filters expose Importance and Urgency as independent minimum-threshold rows while retaining their combined matching semantics.
- Mac Home uses a root-owned SwiftUI top toolbar chrome aligned to the macOS traffic-light titlebar band in normal windows. The Home split content is laid out underneath that chrome instead of being covered by it, and the toolbar is one titlebar-height row rather than a search row plus a second command row. In fullscreen, Home observes only the window fullscreen state and integrates the native titlebar/traffic-light reserve into that existing top toolbar chrome; it does not add a separate blank band above the toolbar, observe pointer-revealed titlebar state, or add/remove top padding while the pointer moves. The sidebar toggle sits in the lower-left titlebar pocket below the native traffic lights, while the rest of Routina's toolbar controls start after the toolbar's leading traffic-light-safe region, and the sidebar and main content remain below the custom toolbar row. Fullscreen Home disables full-size transparent titlebar content and avoids ignoring the top safe area so sidebar or split-view surfaces cannot show a rounded top edge behind the traffic lights; normal non-fullscreen windows keep full-size transparent titlebar content for their existing custom toolbar alignment. A leading sidebar control in the toolbar row explicitly collapses or expands the left Home sidebar with the normal sidebar animation, and it stays available after collapse because it lives in the top toolbar rather than inside the sidebar. While a Focus or sprint timer runs, its compact live-time badge appears immediately to the right of that toggle and opens the timer's available controls. While visible, the Home sidebar is clamped to its configured minimum and maximum widths so dragging the divider cannot make it consume the main workspace, and restoring the sidebar does not grow the Home window, animate right-side companion panes off the window edge, or make companion/task-detail surfaces brighten, duplicate, or ghost during sidebar visibility or task-detail expand/minimize transitions. The Done status badge is hidden by default and can be restored with Settings -> Appearance -> Toolbar -> `Show Done count in toolbar`. Development builds also show an orange `Dev Version` badge by default; Settings -> Appearance -> Toolbar -> `Show development badge` can hide only that badge temporarily without changing the app's development data identity. One labeled workspace control owns a single native menu whose first group starts with `Add New Task` and `Focus`, including their visible Control-Option-Command-T/F shortcuts and any enabled feature-gated creation actions. A divider separates those actions from Planner, Backlog, Task Ladder, and the other enabled workspace destinations; another divider separates Settings. There is no separate `+` toolbar target. Planner, Backlog, and Task Ladder share the centered SwiftUI-owned search/create pill with independent workspace queries; Stats, Adventure, and Add Task hide it and dismiss active toolbar search focus when entered. Places when enabled, the optional Stats/Adventure progress picker, and the board inspector button also live in this row when available. The SwiftUI-owned search pill is compact when idle and animates to a wider focused width when the user is searching or creating. The idle empty pill uses a distinct closed color treatment and centers its magnifying-glass icon and placeholder as one group. Focused search uses its own active background and stroke, keeps the icon and editor left-aligned, and shows an I-beam cursor across the full visible pill. Its rounded background, stroke, magnifying-glass icon, placeholder, clear button, create hint, and `Esc` keycap animate together and stay bounded inside the pill; typing and first-responder ownership are handled by a transparent AppKit text editor inside that shell. Clicking any visible area inside the pill, including empty shell areas, focuses the editor. Focused search can be dismissed without clearing the query by clicking outside the visible search pill, pressing `Esc`, or using the toolbar search `Esc` keycap button, while the in-field clear button clears the query. It uses the shared Home search text so task lists, Timeline-style lists, the Planner Timeline segment's full Timeline surface, and task-backed Planner Calendar items can be searched from the top of the window. The field placeholder names both search and task creation, and a compact `Return` / `Create task` hint appears when the focused non-empty query has no matching task or timeline result. When that focused create-eligible query also contains quick-add syntax such as due words, recurrence, tags, places, priority, or duration, a flat parser preview attaches below the toolbar chrome showing the cleaned task title and detected details without duplicating the `Return` / `Create task` hint. The configurable Mac Quick Add shortcut focuses this toolbar field only while it is visible. Pressing Return with a non-empty query creates a task through the shared Quick Add parser only when the query has no task or timeline result; otherwise the field remains a live search. Pressing Command-Return with a non-empty focused query opens the full Mac Add Task form, seeds the Identity task-name field with the trimmed query, dismisses toolbar search focus, and clears the toolbar search text. Successful toolbar creation clears search and shows the created-task toast, and creation errors use a Home alert; task count never blocks creation. The workspace menu omits Timeline because Planner `Timeline` is the timeline review route, and the former top toolbar filter icon is removed. Choosing `Focus` from the combined menu opens one sheet that owns duration and task/tag attribution and defaults from the latest attributed Focus choice. The Planner header does not repeat Focus or change its date-button presentation when Focus state changes; active timers remain manageable from the live Home badge and existing macOS timer/status menu. The Planner header filter button opens Home-level filters in a right-side `All` / `Task List` / `Timeline` / `Calendar` companion pane; Tags plus independent Importance, Urgency, Pressure, Thinking needed, and Estimated time controls live under `All` and apply across Task List, task-backed Timeline activity, and task-backed Calendar items. Importance, Urgency, and Pressure use each task's current `Now` value; the Tags card shows only active rules until a searchable Add-tag picker deliberately opens the full catalog. Timeline has no range filter, and Calendar owns Planner layer visibility filters. In Planner Timeline mode, `Go to date` remains visible beside filters, uses a single selected date instead of the Calendar visible range, and opens the right-side Planner date picker without scoping the Timeline list; selecting a date scrolls to the matching visible Timeline day when that day exists. Task and compatibility Timeline sidebars do not render duplicate search fields or filter icon buttons for that same toolbar area, though they may show active-filter summaries and clear actions. The toolbar field restores first responder after search updates so typing stays focused there, but it does not reclaim focus after the user moves into another text editor such as task comments or notes.
- Current Mac filter placement is workspace-level: one full-surface filter button sits immediately left of the combined workspace menu only in Planner and Backlog. The persistent menu stays at the command cluster's trailing edge, so switching to a workspace that hides Filters does not shift the menu. Planner has no duplicate local-header filter and opens its established `Shared` / `Task List` / `Timeline` / `Calendar` surface; Backlog opens independent task filters in the same companion/fullscreen presentation pattern. Task Ladder, Stats, Settings, Details, and other workspaces omit the toolbar filter. A non-default active-workspace filter tints the icon.
- The combined Mac workspace menu begins with Add New Task and Focus before a divider and the workspace destinations. Its Focus row derives availability from the eligible active-task snapshot used by the Focus sheet rather than from visible or filtered Home rows. An active Focus or sprint timer and a genuinely empty eligible snapshot still disable the row; only the active-timer case adds a visible `Another timer is running` explanation directly beneath Focus in the open menu.
- For an exact one-off availability date and time, the Mac toolbar parser preview is interactive before creation and asks for `No reminder`, `1 hour before`, `2 hours before`, `1 day before`, or `Custom date/time`. No reminder is the default. The search pill and its attached preview form one interaction boundary: opening or choosing a reminder menu item, editing the proposed title, or using the custom date picker keeps the preview open. Clicking elsewhere in the same Home window or pressing `Esc` dismisses it. The chosen relative reminder is anchored to the parsed availability time and is saved with the task when Return creates it.
- For a pasted web link, the Mac toolbar parser preview immediately shows the detected source and an editable task title. Public-link metadata resolves asynchronously with a small progress indicator; an untouched URL-only fallback can become a page-specific task title, while any user edit remains authoritative. Return uses the currently displayed title without waiting for metadata.
- Successful Mac task creation shows a transient confirmation containing the task name. Toolbar Quick Add keeps `Open details` because it preserves the current workspace; full Add Task omits that action because the new task's details are already selected and visible. Toast actions and close controls align to the panel's normal trailing inset.
- When a non-empty Mac Home toolbar search query has no matching task or timeline result and the task-list sidebar is empty, the sidebar uses the Planner Timeline no-results subtext, `Try a different timeline search or filters.`, and shows a `Create task` button. The button opens the full Mac Add Task form through the same seeded route as Command-Return, putting the trimmed query into the Identity task-name field, dismissing toolbar search focus, and clearing the toolbar search text.
- Every non-empty Mac Home toolbar task search merges eligible known matches from outside normal active placement into a trailing `Search Results` section, even when ordinary task-list sections also contain matches. Rows already visible in ordinary or `Hidden by flag` sections are excluded from that fallback, so broad and refined queries remain consistent without duplicate tasks.
- When a Mac Home toolbar search query first becomes non-empty, Home captures the current left-sidebar visibility and task-list collapse state, temporarily reveals the sidebar column, and treats all task-list super sections and nested groups as expanded so matching rows are visible without extra clicks. Clearing the query restores the captured sidebar visibility and task-list collapse state from before the search session.
- In Planner Timeline mode, the top-toolbar filter button reflects active Timeline filters and opens the `Timeline` scope of the companion filter pane. Flag filtering is not repeated there: Mac `Shared` owns an always-expanded, titled orange `Flags` panel for task-backed Task List, Timeline, and Calendar content, while Tags use a separate titled teal panel. Each panel has one edit action that opens a combined searchable Include/Exclude popover; All/Any appears there only when the selected side contains multiple values. An idle panel places the edit action directly below its title without a `No filters` line; an active panel keeps Include and Exclude chips directly visible and removable, including each meaningful match mode. Include can deliberately recover normally hidden Flag matches, and Exclude wins Flag overlaps. Calendar keeps its separate `Assumed done` toggle because that switch controls a Calendar activity layer rather than filtering tasks by Flag assignment.
- The former compact Mac mode strip is replaced by the labeled workspace menu. Settings remains a separate macOS window, but its menu entry keeps it discoverable beside the primary workspaces.
- On Mac, task detail presentation follows the active workspace. Mac Home opens at 1440 x 760 and cannot resize below 1440 x 720, keeping enough horizontal room for the expanded left sidebar, a Day-capable Planner surface, and a right-side companion pane during sidebar animation. When Planner is active, single-click task-list selection and Planner task selection open a right-side companion detail pane beside the calendar when the detail area can fit the fixed companion pane plus a Day-capable Planner surface. At tight widths, the Planner calendar can adapt down to a compact Day layout to make room for the pane. The Planner header keeps its view, Calendar task-view, and range controls available as compact current-value triggers that reveal one segmented choice set at a time, lists only ranges the remaining calendar width can render, and makes Go to date icon-only when the header needs the additional room. The task-detail companion pane does not render a separate `Task Details` toolbar strip; its fullscreen and close controls live in the compact task header action cluster beside the completion action. Home filter companion panes keep their pane header controls, and fullscreen views opened from companion panes can minimize back to the previous pane layout. Those panes are mutually exclusive with each other, Planner's internal right sidebar, and the board inspector. Full Details close still returns to Planner and clears the task-detail pane. Double-clicking a Mac task-list row opens the full Details surface.
- On Mac, task details show the selected task's current visible sidebar section/subsection path as a clickable breadcrumb directly below the task title and above status, completion, and other metadata. Clicking it, or pressing Command-Shift-L while task details are visible, reveals the left task-list sidebar, expands the containing task-list section and nested groups as needed, and scrolls to the selected task when its row is present in the current task-list presentation. If the row is not currently available there, the breadcrumb is absent and the shortcut shows an informational toast instead of changing filters.
- Mac task-detail actions render as one explicitly spaced top-right control cluster inside the task detail header card rather than in the app toolbar, so task-specific actions stay owned by the selected task and do not compete with toolbar search. Full Details joins `Done` and `⋮` into one lifecycle control with a shared rounded outer shape: Done remains the leftmost and only prominent task action with its semantic completion tint, while a divider separates the narrow neutral overflow segment. Only that `⋮` segment receives a restrained accent treatment while its native menu is open. Repeating tasks offer Pause/Resume, one-time tasks offer Archive/Restore and eligible `Cancel one-time task`, and a separated red Delete item keeps its confirmation dialog. Link, sharing, minimize, and close remain icon controls, with close as the single rightmost `xmark` for leaving Full Details. Edit is a split control while optional fields remain: its pencil segment opens full Edit Task directly, and its narrow chevron opens an anchored `Add a detail` popover with the available count and a single-column list. Only the chevron receives the active accent treatment, and the chevron disappears when the catalog is empty. The right-side task-detail companion pane uses the compact variant: its completion action remains standalone beside fullscreen and close because the pane omits the overflow menu, link/share, and editing controls.
- Full Mac Task Details has no scrolling Add More card. The header chooser reveals detail-owned content directly and form-backed metadata inline with local Cancel/Save. The optional done heatmap remains hidden by default for repeating routines and persists per task when added; iOS, companion panes, and todos omit that action. Full Mac Task Details omits the `Events` chooser while the Event/Emotion experiment is off. Mac Add Task and Edit Task keep the normal task-list sidebar visible, use a centered readable width, and keep progressive disclosure inside the form. Identity owns title and validation. `Behavior & Schedule` owns completion, cadence, due style, availability, planning, badge preview, deadline, and reminder as applicable. `Task Ladder values` owns Importance, Urgency, Pressure, Thinking, and Changes over time. `Organization` owns Path, Tags, Flags, and repeating-task Task Ladder grouping. Cancel/Save stays in Identity; Emoji, Image, and other rich details remain optional sections.
- Active task Focus forces its timer controls open. While that force is active, the Mac Effort header and any visible standalone Focus header are static and omit the disclosure chevron because collapse is unavailable. When the session ends, the ordinary clickable disclosure header and chevron return.
