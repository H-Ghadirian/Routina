## Current Contract

- Visible button targets are interactive across their full visual surface, not only across their text, emoji, or icon.
- Native SwiftUI button styles may own their native hit areas.
- Custom or plain buttons must make the intended button surface fill the target and define a matching `contentShape`.
- Routina glass-backed cards, pills, and panels provide rounded hit shapes through their shared visual modifiers so new glass-backed buttons inherit the rule by default.
- Shared glass segmented controls keep selected labels dark against their bright selected glass surface in both light and dark appearance.
- The iOS Home Filters Task Type control uses text-only `All`, `Routines`, and `Todos` segments with compact padding and enough minimum width to keep every label complete inside the filter sheet.
- iOS Home, Stats, and Timeline Filters show their available choices together as compact current-value rows without a separate heading repeating a row's name. A Priority heading groups the independently named Importance and Urgency rows on all three surfaces plus Pressure and Thinking needed on Home. Each row opens a persistent detail sheet whose navigation title names the choice once; inline pickers suppress the same visible label while retaining their accessibility label. The Tags entry opens the searchable catalog only when selected, so the primary filter sheet never expands every saved tag. Timeline adds a searchable Flags entry when task-backed activity exposes Flags; selecting one or more deliberately reveals matching activity, including entries hidden from the default Timeline by a Flag rule. Clear Filters remains a separate direct primary-sheet action.
- iOS collapsible Home section headers show their compact task count with secondary contrast so the number remains readable in light and dark appearance.
- iOS Timeline renders from a stable explicit SwiftData snapshot and refetches it on appearance, app activation, and Routina's semantic update notification so newly imported CloudKit activity appears without reopening the app or waiting for a long-lived query to invalidate.
- iOS Timeline's Type sheet and horizontal type controls follow feature availability. Events and Emotions require `Show Event and Emotion actions`; Sleep requires both `Show Away` and `Show Sleep tab`; Notes, Places, and Away retain their own gates. Turning a gate off removes its type choice immediately and normalizes a stale selection back to `All`, so unavailable selections do not remain active or keep the filter button highlighted.
- The iOS bottom-bar `New` action always offers Task. Production has no Beta Experiment actions, so New routes directly to task creation. Development builds derive optional actions from experiment availability: Event and Emotion follow their experiment, Goal follows `Show Goals tab`, Note follows `Show Notes`, Check In follows `Show Places`, Away follows `Show Away`, and Going to sleep requires Away, the nested Sleep experiment, and its dedicated New-sheet shortcut preference. When exactly one action is available, New opens it directly; with two or more actions, New presents the chooser.
- A truly empty iOS Home list shows `Add New Task`. When a non-empty Home search has no matching known task, its no-results state shows `Create Task`; both actions open the shared Smart Add sheet, and the search action pre-fills it with the trimmed query. If a known task matches but current filters hide it, Home omits the create action to avoid suggesting a duplicate.
- Compact iOS More keeps `Review tasks` as its dedicated task-review destination. It contains `Help me choose` first, then a clearly labeled `Add missing task details` group for time estimates, Pressure, Thinking needed, Importance, and Urgency. The root More list stays concise while the native navigation stack preserves a normal back path through each review.
- `Help me choose` lets the person select available time, current energy, and whether they want to reduce pressure, meet urgency, or make progress. It requires every currently selectable task to have explicit Importance and Urgency plus Pressure, Thinking needed, and a time estimate; missing-field counts direct the person to the matching review. Canceled, paused, snoozed, assumed-done, and current-period-complete tasks, plus tasks with a confirmed unresolved `Blocked by` prerequisite, are excluded before readiness and ranking. Once ready, the reducer compares only tasks that are equally relevant for the chosen condition and have an equal learned tie-break. Each choice persists a separate task-choice score and comparison count, then moves to the next unresolved tie; the score is never presented as or allowed to change Importance, Urgency, Pressure, Thinking needed, Priority, duration, planning, scheduling, or order. When no relevant ties remain, it recommends the highest-ranked task and can open the existing Home task details. The MVP has no macOS entry point.
- `Add missing time estimates` presents the existing 15m, 30m, 1h, 2h, 4h, 8h, and 20h duration presets together in a two-row, full-height guided card for repeating tasks without an estimate and unfinished, uncanceled one-off tasks without one. Always-visible custom Hours and Minutes inputs offer a direct alternative. A selected preset or custom time remains visibly drafted until `Save & next` persists `estimatedDurationMinutes` and advances; Skip and Check task details retain the shared guided-review behavior. It never changes actual time spent, priority metadata, planning, scheduling, or order. The MVP has no macOS entry point.
- `Add missing Pressure data` presents repeating tasks whose Pressure is still `None`, plus one-off tasks only while unfinished and not canceled, as a single full-height card with the title, custom-section path, up to three tags, up to three planning or status labels (such as `Planned today`), the pressure question, and `Low`, `Medium`, or `High` choices; choosing a value saves it and advances to the next card without a scrolling list. A compact `Task n of total` progress header has dedicated clearance below the inline navigation title, so it never overlaps the destination name. Completed or canceled one-off tasks never appear. Each card can skip to the next missing task without changing its data, or open the existing Home task details. The MVP has no macOS entry point.
- `Add missing Thinking needed data` presents the same one-card flow for repeating tasks whose Thinking needed is `None`, plus unfinished, uncanceled one-off tasks. The card explains that this is the concentration, understanding, or decision-making required, offers direct `Low`, `Medium`, and `High` choices, and preserves the same bounded context, progress header, Skip, and Check task details actions. Saving changes only Thinking needed; it never changes pressure, priority, duration, or scheduling. The MVP has no macOS entry point.
- `Review Importance` and `Review Urgency` remain separate procedures. Each presents one larger card at a time for lifecycle-eligible tasks whose own field is not yet explicit. The compact progress header remains below the inline navigation title, while the card keeps its title at the top and the actions reachable at the bottom. All four values are visible immediately in a two-by-two selector; choosing one saves and advances, while `Skip` and `Check task details` remain available. Completing one review does not hide the other: `hasExplicitImportance` and `hasExplicitUrgency` persist independently, including deliberate legacy `Medium` choices. The legacy defaults remain Medium until [debt ticket 0001](../debt/0001-make-importance-and-urgency-explicitly-optional.md) migrates both fields to explicit `None` values.
- iOS and Mac Add/Edit present Importance and Urgency as separate four-level controls, with the same visual treatment as Pressure and Thinking needed. iOS Task Details can add either field independently with separate picker pills. Mac Task Details keep the four independent Importance, Urgency, Pressure, and Thinking needed controls together inside the expandable Priority card. Saving one field never marks the other explicit. Derived Priority remains internal sorting metadata. iOS Home, Stats, and Timeline filters expose Importance and Urgency as independent minimum-threshold rows while retaining their combined matching semantics.
- Mac Home uses a root-owned SwiftUI top toolbar chrome aligned to the macOS traffic-light titlebar band in normal windows. The Home split content is laid out underneath that chrome instead of being covered by it, and the toolbar is one titlebar-height row rather than a search row plus a second command row. In fullscreen, Home observes only the window fullscreen state and integrates the native titlebar/traffic-light reserve into that existing top toolbar chrome; it does not add a separate blank band above the toolbar, observe pointer-revealed titlebar state, or add/remove top padding while the pointer moves. The sidebar toggle sits in the lower-left titlebar pocket below the native traffic lights, while the rest of Routina's toolbar controls start after the toolbar's leading traffic-light-safe region, and the sidebar and main content remain below the custom toolbar row. Fullscreen Home disables full-size transparent titlebar content and avoids ignoring the top safe area so sidebar or split-view surfaces cannot show a rounded top edge behind the traffic lights; normal non-fullscreen windows keep full-size transparent titlebar content for their existing custom toolbar alignment. A leading sidebar control in the toolbar row explicitly collapses or expands the left Home sidebar with the normal sidebar animation, and it stays available after collapse because it lives in the top toolbar rather than inside the sidebar. While visible, the Home sidebar is clamped to its configured minimum and maximum widths so dragging the divider cannot make it consume the main workspace, and restoring the sidebar does not grow the Home window, animate right-side companion panes off the window edge, or make companion/task-detail surfaces brighten, duplicate, or ghost during sidebar visibility or task-detail expand/minimize transitions. The Done status badge is hidden by default and can be restored with Settings -> Appearance -> Toolbar -> `Show Done count in toolbar`. Development builds also show an orange `Dev Version` badge by default; Settings -> Appearance -> Toolbar -> `Show development badge` can hide only that badge temporarily without changing the app's development data identity. The compact Tasks/Stats/Add mode strip lives in the same row, and the SwiftUI-owned search pill sits centered in that row only on searchable Home surfaces. Stats, Adventure, and Add Task hide the search pill and dismiss active toolbar search focus when entered. Places when enabled, the optional Stats/Adventure progress picker, and the board inspector button also live in this row when available. The SwiftUI-owned search pill is compact when idle and animates to a wider focused width when the user is searching or creating. The idle empty pill uses a distinct closed color treatment and centers its magnifying-glass icon and placeholder as one group. Focused search uses its own active background and stroke, keeps the icon and editor left-aligned, and shows an I-beam cursor across the full visible pill. Its rounded background, stroke, magnifying-glass icon, placeholder, clear button, create hint, and `Esc` keycap animate together and stay bounded inside the pill; typing and first-responder ownership are handled by a transparent AppKit text editor inside that shell. Clicking any visible area inside the pill, including empty shell areas, focuses the editor. Focused search can be dismissed without clearing the query by clicking outside the visible search pill, pressing `Esc`, or using the toolbar search `Esc` keycap button, while the in-field clear button clears the query. It uses the shared Home search text so task lists, Timeline-style lists, the Planner Timeline segment's full Timeline surface, and task-backed Planner Calendar items can be searched from the top of the window. The field placeholder names both search and task creation, and a compact `Return` / `Create task` hint appears when the focused non-empty query has no matching task or timeline result. When that focused create-eligible query also contains quick-add syntax such as due words, recurrence, tags, places, priority, or duration, a flat parser preview attaches below the toolbar chrome showing the cleaned task title and detected details without duplicating the `Return` / `Create task` hint. The configurable Mac Quick Add shortcut focuses this toolbar field only while it is visible. Pressing Return with a non-empty query creates a task through the shared Quick Add parser only when the query has no task or timeline result; otherwise the field remains a live search. Pressing Command-Return with a non-empty focused query opens the full Mac Add Task form, seeds the Identity task-name field with the trimmed query, dismisses toolbar search focus, and clears the toolbar search text. Successful toolbar creation clears search and shows the created-task toast, and creation errors use a Home alert; task count never blocks creation. The visible mode strip omits Timeline because Planner `Timeline` is the timeline review route, and the former top toolbar filter icon is removed. The Planner header shows Focus beside the filter button in both Calendar and Timeline modes; the Focus control keeps task-picker duration starts, active plan-focus controls, and active non-plan focus badges throughout Planner. The Planner header filter button opens Home-level filters in a right-side `All` / `Task List` / `Timeline` / `Calendar` companion pane; shared tag and importance/urgency filters live under `All`, Timeline has no range filter, and Calendar owns Planner layer visibility filters. In Planner Timeline mode, `Go to date` remains visible beside filters, uses a single selected date instead of the Calendar visible range, and opens the right-side Planner date picker without scoping the Timeline list; selecting a date scrolls to the matching visible Timeline day when that day exists. Task and compatibility Timeline sidebars do not render duplicate search fields or filter icon buttons for that same toolbar area, though they may show active-filter summaries and clear actions. The toolbar field restores first responder after search updates so typing stays focused there, but it does not reclaim focus after the user moves into another text editor such as task comments or notes.
- Successful Mac task creation shows a transient confirmation containing the task name. Toolbar Quick Add keeps `Open details` because it preserves the current workspace; full Add Task omits that action because the new task's details are already selected and visible. Toast actions and close controls align to the panel's normal trailing inset.
- When a non-empty Mac Home toolbar search query has no matching task or timeline result and the task-list sidebar is empty, the sidebar uses the Planner Timeline no-results subtext, `Try a different timeline search or filters.`, and shows a `Create task` button. The button opens the full Mac Add Task form through the same seeded route as Command-Return, putting the trimmed query into the Identity task-name field, dismissing toolbar search focus, and clearing the toolbar search text.
- When a Mac Home toolbar search query first becomes non-empty, Home captures the current left-sidebar visibility and task-list collapse state, temporarily reveals the sidebar column, and treats all task-list super sections and nested groups as expanded so matching rows are visible without extra clicks. Clearing the query restores the captured sidebar visibility and task-list collapse state from before the search session.
- In Planner Timeline mode, the Planner header filter button reflects active Timeline filters and opens the `Timeline` scope of the companion filter pane. Its Flags section defaults to the ordinary Timeline and can reveal task activity by one or more selected Flags with `All` / `Any` matching.
- The compact Mac Home toolbar mode strip omits Settings. The underlying Settings mode and routes remain available outside that toolbar strip.
- On Mac, task detail presentation follows the active workspace. Mac Home opens at 1440 x 760 and cannot resize below 1440 x 720, keeping enough horizontal room for the expanded left sidebar, a Day-capable Planner surface, and a right-side companion pane during sidebar animation. When Planner is active, single-click task-list selection and Planner task selection open a right-side companion detail pane beside the calendar when the detail area can fit the fixed companion pane plus a Day-capable Planner surface. At tight widths, the Planner calendar can adapt down to a compact Day layout to make room for the pane, and the Planner header hides the Day/3 Days/Week picker unless the companion layout has roomy inspector width. Hiding that picker does not by itself make Calendar/Timeline icon-only or shorten the date/range button; if the header narrows further, Calendar/Timeline text hides before the date/range button switches to compact width. The task-detail companion pane does not render a separate `Task Details` toolbar strip; its fullscreen and close controls live in the compact task header action cluster beside the completion action. Home filter companion panes keep their pane header controls, and fullscreen views opened from companion panes can minimize back to the previous pane layout. Those panes are mutually exclusive with each other, Planner's internal right sidebar, and the board inspector. Full Details close still returns to Planner and clears the task-detail pane. Double-clicking a Mac task-list row opens the full Details surface.
- On Mac, task details show the selected task's current visible sidebar section/subsection path as a clickable breadcrumb directly below the task title and above status, completion, and other metadata. Clicking it, or pressing Command-Shift-L while task details are visible, reveals the left task-list sidebar, expands the containing task-list section and nested groups as needed, and scrolls to the selected task when its row is present in the current task-list presentation. If the row is not currently available there, the breadcrumb is absent and the shortcut shows an informational toast instead of changing filters.
- Mac task-detail actions render as one explicitly spaced top-right control cluster inside the task detail header card rather than in the app toolbar, so task-specific actions stay owned by the selected task and do not compete with toolbar search. `Done` is always the leftmost action and is the only prominent task action, using a fixed-height custom rounded-rectangle label so its short text does not collapse into a circle. Full Details collects secondary task lifecycle actions in a compact native `⋮` menu: its trigger has no idle container and receives a circular accent highlight only while the menu is open; routines show Pause/Resume, one-off tasks show Archive/Restore and eligible `Cancel todo`, and a separated red Delete item keeps its confirmation dialog. Link, sharing, edit, minimize, and close render as equal-size icon controls, with close remaining the single rightmost `xmark` for leaving Full Details. The right-side task-detail companion pane uses the compact variant: completion action plus fullscreen and close only, omitting the overflow menu, link/share, and edit controls. Full Mac Task Details keeps `Add more details` metadata actions in the detail screen: detail-owned controls reveal directly, and form-backed metadata actions reveal the selected editor card inline with local Cancel/Save instead of switching to full Edit Task. The optional done heatmap is hidden by default for routine and tracking tasks, but adding `Heatmap` persists that choice on the selected task so future full Mac Details for that same task show it; other tasks remain unchanged, and iOS, Mac companion panes, and todos omit the heatmap action. Full Mac Task Details omits the `Add more details` Events action while Settings -> General -> Beta Experiments -> `Show Event and Emotion actions` is off. Mac Add Task and Edit Task keep the normal task-list sidebar visible instead of replacing it with form-section titles; progressive disclosure and section scrolling remain inside the form. Full Mac task forms use a centered readable maximum width rather than stretching cards across the entire detail canvas. Their Behavior card keeps routine schedule behavior, completion, and task-list badge preview together, uses intrinsic content height, and reserves a secondary column only for todo reminder/deadline controls when space permits. Eligible routine Planning lives inside `Schedule details` and never enters the routine `Add More Details` palette, while todo Planning remains an optional standalone section. Mac task form creation and inline editing keep Cancel/Save inside the Identity section rather than in the app toolbar. Identity contains the title, validation, and title-derived preview rather than media controls; Emoji and Image are separate optional form sections available through `Add More Details`, while customized saved emoji remains visible during progressive editing.
