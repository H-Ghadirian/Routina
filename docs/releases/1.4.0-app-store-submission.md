# Routina 1.4.0 App Store Submission Checklist

Status: In preparation

Public version: 1.4.0

Build: 12

Last reviewed: 2026-08-30

This checklist covers the iPhone app and the macOS app. It does
not mark either version as released. Complete the final build, metadata, upload,
review, and shipment steps before changing the platform notes to `Released`.

## Repository documentation

- [x] Draft independent [iPhone](ios/1.4.0.md) and
  [macOS](macos/1.4.0.md) release notes, and mark the prepared
  [iPad](ipados/1.4.0.md) candidate as deferred before release.
- [x] Store the draft macOS [App Store Description and What's New copy](macos/1.4.0-app-store.md)
  in its versioned metadata document.
- [x] Record that the aligned [watchOS](watchos/1.4.0.md) companion remains
  deferred and is not embedded in the production iOS app.
- [x] Update the combined [support, Privacy Policy, and Terms of Use source](<../../privacy policy & terms of use/index.html>)
  for Firebase Crashlytics, current production permissions, the optional Mac AI
  connection, public-link metadata lookup, third-party accounts and content, and
  AI-output limitations.
- [x] Preserve the stable support, `#privacy`, and `#terms` anchors used by both
  apps.

## Public website and App Store Connect

- [ ] Publish the updated support/privacy/terms page at
  `https://h-ghadirian.github.io/` before submitting either app for review.
- [ ] Verify that the public root page and the `#privacy` and `#terms` anchors
  load without authentication.
- [ ] Confirm the Privacy Policy URL for the iOS and macOS platforms is
  `https://h-ghadirian.github.io/#privacy`.
- [ ] Review the final archives' generated privacy reports. For the current
  Crashlytics integration, the expected App Store privacy answers include
  `Crash Data` and `Other Diagnostic Data`, used for `App Functionality`, not
  linked to identity, and not used for tracking. If the final archive reports
  additional collection, disclose the inclusive result instead of copying this
  expectation mechanically.
- [ ] Publish the updated App Privacy answers in App Store Connect. Apple
  requires the answers to include third-party SDK practices and to represent the
  most data-collecting platform attached to the app record.
- [ ] Prepare platform-specific Promotional Text / What's New copy from the
  corresponding 1.4.0 release note instead of reusing one platform's list.

Apple references:

- [Manage app privacy](https://developer.apple.com/help/app-store-connect/manage-app-information/manage-app-privacy/)
- [App privacy details](https://developer.apple.com/app-store/app-privacy-details/)
- [Firebase Crashlytics privacy manifest](https://github.com/firebase/firebase-ios-sdk/blob/main/Crashlytics/Resources/PrivacyInfo.xcprivacy)

## Production scope and capabilities

- [ ] Confirm the final iOS archive contains the iPhone-only app and production
  widget, but no iPad device-family declaration, Watch app, or Watch extension.
- [ ] Confirm the final iOS archive contains no Apple Health UI or HealthKit
  entitlement and no Health privacy-purpose strings.
- [ ] Confirm production iOS omits Places location services and Screen Time
  blocking, and production macOS omits experimental location, microphone, and
  Apple Events automation capabilities.
- [ ] Confirm Apple Calendar import remains declared and functional on both
  platforms; Outlook appears only when a valid Microsoft Graph client ID is
  supplied.
- [ ] Confirm both production bundles retain
  `ITSAppUsesNonExemptEncryption = false`; reassess before relying on it if the
  final dependency or feature set adds non-exempt encryption.

## CloudKit, Crashlytics, and archives

- [ ] Deploy every release schema change to the CloudKit Production environment.
- [ ] Run the production-schema acknowledgement command and commit the resulting
  `Config/CloudKit/production-schema.manifest` state before creating final
  archives.
- [ ] Confirm the production Firebase configuration matches
  `ir.hamedgh.Routinam` and is copied into both production app bundles.
- [ ] Confirm Google Analytics is absent, Crashlytics collection matches the
  published policy, and the final iOS and macOS archives include the SDK privacy
  manifests.
- [ ] Confirm dSYMs upload for each app and that the macOS archive contains a
  matching dSYM for `RoutinaAIMCPServer`.
- [ ] Confirm every executable inside the macOS archive is sandboxed and the MCP
  helper carries only App Sandbox and inheritance entitlements.

## Final verification and shipment

- [ ] Run the final automated tests from the exact release worktree state.
- [ ] Build and launch the final production-scoped iOS app on an intended iPhone
  simulator or device and the final macOS app on macOS.
- [ ] Upload the final archives and resolve any App Store Connect validation,
  privacy, export-compliance, symbol, or capability warning before review.
- [ ] After each platform actually ships, change only that platform's 1.4.0 note
  to `Released` and record its distribution date. Keep an unshipped platform in
  `In development`.
